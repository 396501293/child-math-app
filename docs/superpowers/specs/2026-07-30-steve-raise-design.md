# 史蒂夫养成（奖励模块）设计规范

> 状态：待评审 · 2026-07-30
> 经济数值与教育约束的**权威来源**是 `docs/edu-pm-reviews/2026-07-30-steve-raise-review.md`（下称「评审」）
> 及其继承的 `2026-07-29-rewards-module-review.md`。本文只把它们翻译成工程契约；
> 两处冲突时以评审为准。

## 0. 已拍板决策（不再重议）

| 决策 | 结论 |
|---|---|
| 载体 | 史蒂夫装备阶梯 + 配件 + 星空点星，无终局分层结构 |
| 里程碑粒度 | **按件获得**：4 阶 × 靴/盔/腿/胸 4 件 = 16 次里程碑（评审遗留 1，用户批准） |
| 答题屏着装 | **穿当前装备**，装备在答题屏内无任何动效（评审遗留 2，用户批准） |
| 顶栏计数 | **只显煤**——五矿加总是错误的加法模型，数学 App 顶栏不挂错误数学（评审问 0，用户批准） |
| 配件获得 | 工作台**制作**（孩子主动触发），非自动掉落；措辞永远「做」不「买」 |
| 星空 | 保留，**只收煤**，10 煤/颗固定价；点亮的星常驻地图背景夜空 |
| 装备耐久 | **无**。不破损、不丢失、不被没收；家长关开关后史蒂夫保持装扮 |

## 1. 目标与非目标

把四条互不相通的进度（主线/无尽/冲刺/星图）汇进一个容器，给孩子第一个可支配
的选择空间。**不是**成就墙：矿石是过去行为的派生记录，装备与星空是花费它们的
自主决策。

非目标（v1 明确不做）：附魔（v1.5）、多孩子档案、任何社交/分享/排行、
配件动画、节日限定内容（评审铁律：无日期依赖）、装备/配件之外的新奖励形态。

## 2. 数据模型

`Progress` 仍为 `version: 2`，新增一个可合并切片（同 `timesTable` 先例，
`storage.ts` 的 merge-over-defaults 天然向后兼容）：

```ts
rewards: {
  practiceFirstTry: number;    // 三练习模式累计首答即对（唯一新埋点）
  owned: string[];             // 已拥有的装备/配件 id（目录见 §4）
  equipped: {                  // 当前穿戴（可逆换装；null = 该槽布衣/空）
    boots: string | null; helm: string | null;
    legs: string | null; chest: string | null;
    accessories: string[];     // 已摆出的配件 id（≤ 每锚点 1 个）
  };
  skyStars: number;            // 已点亮星数（图样按序点亮，见 §4C）
  traded: { coalToIron: number; ironToGold: number; goldToDiamond: number; diamondToEmerald: number };
}
```

**迁移**：`loadProgress` 发现无 `rewards` 切片时，初始化
`practiceFirstTry = endless.totalAnswered`（评审 M5 的「首开惊喜」——老用户
首次打开养成屏时材料已按既往进度堆好），其余为空。

**首答即对埋点**：`App.answer()` 里，非 campaign 模式且 `excluded.length === 0`
时答对 → `practiceFirstTry + 1`。campaign 不计（煤/铁走星级派生）。
星图模式按其自身「首答」语义计（`resolved` 首触即对）。

**每周小结切片（P0-2-lite，评审强烈建议同批交付）**：

```ts
weekly: { weekStart: number; answered: number; firstTry: number } // 仅保留当周，翻周即重置
```

家长设置里显示一行「本周答题 N · 首答正确率 P%」。完整家长小结另立项。

## 3. 核心逻辑 `src/core/rewards.ts`（纯函数，重点测试对象）

```
income(p: Progress): Ores            // 五矿派生（公式见评审 §问3，原样照抄）
spent(r: RewardsSlice): Ores         // 已消耗 = owned 单价和 + skyStars×10 + 兑换净额
balance(p): Ores                     // income − spent，逐项断言 ≥ 0（自愈：可随时重算）
tierUnlocked(r, tier): boolean       // 阶间顺序解锁：上一阶 4 件集齐才开下一阶；皮革恒开
craftable(p, itemId): boolean        // 余额够 && 阶已解锁（配件只看余额）
craft(p, itemId): Progress           // 幂等防重：已拥有则原样返回
lightStar(p): Progress               // 余额 ≥10 煤才可点
trade(p, kind): Progress             // 4:1 只向上
```

收入公式（照抄评审，一个数不改）：
煤 `#{star≥1} + floor(P/8)`；铁 `Σ(star−1)`；金 `floor(P/25)`；
钻 `floor(N★/10) + floor(P/200)`；绿 `floor(litBest/3) + floor(bestStreak/10)`。

## 4. 目录常量（数值照抄评审 §数值规范表）

**A. 装备**（id `eq-{tier}-{slot}`）：皮革 3/6/9/12 煤 · 铁 5/8/12/15 铁 ·
金 3/5/7/9 金 · 钻 2/2/3/5 钻（件序恒为 靴/盔/腿/胸）。

**B. 配件 12 件**（id `ac-*`）：火把 5 煤/灯笼 10 煤/木镐 8 煤/钓鱼竿 8 煤/
花盆 6 煤/蛋糕 12 煤/旗帜 12 煤/盾牌 15 煤/小鸡 4 铁/小狗 6 铁/鹦鹉 2 绿/小猫 3 绿。
锚点：手持/脚边/肩侧/站边，每锚点同时只摆 1 个。

**C. 星空**：v1 图样 小船7/北斗7/灯塔9/月亮10/鲸鱼12（共 45 星），按图样顺序
点亮；45 星之后自由点星无上限。星座集齐 = 连线亮起 + 一句语音，无其他奖励。

**D. 兑换**：`4 煤→1 铁→1 金→1 钻→1 绿`，只向上。3:1 是唯一调参备用旋钮。

## 5. 屏幕与入口

**Screen 增至五个**：`'map' | 'quiz' | 'result' | 'starchart' | 'steve'`。

- **主入口**：地图屏点史蒂夫卡片 → `'steve'`；原念台词行为移到 🔊 徽标
  （`stopPropagation`）。进屏念一句欢迎台词（孩子识字有限，导航靠语音）。
- **辅入口**：地图顶栏 ★ 旁加煤计数（`Ico` 风格 + 数字，静态）。
  **只在地图屏**；任何答题屏顶栏都不出现。
- **养成屏两个标签**：
  - **装备**：左列 4 阶纵向列表（渐次显形：已解锁阶展开 4 件；下一阶只剩
    剪影 + 价格；再往后不显示）；中央史蒂夫大立绘（当前穿戴，点件即穿/脱）；
    价格用点阵成组渲染（M3：12 煤 = 两组 5 + 2）。
  - **工作台**：配件目录（渐次显形：已拥有 + 接下来 2–3 件，无「?」占位）、
    兑换 4 条、点星入口。三种花费共用一套点阵价格渲染与确认语音。
- **地图夜空层**：已点亮的星渲染进地图屏背景（CSS 绝对定位小方点，位置由
  图样常量决定），星座集齐后连线常驻。零素材成本。
- **结算入账**：结算卡内加一行本局增量（`income(after) − income(before)`），
  格式「+2 煤」，静态出现 ≤1s，无强音效、无滚动数字（M1）。

## 6. 呈现纪律 → 工程约束（实现时的硬检查单）

1. 矿石元素**零出现**于任何答题屏（计数/动画/音效）——M1
2. 全部文案禁「买/钱/商店/奖励你/赢得」与未来式许诺；材料「做」装备——M2
3. 地图入口无红点/角标/发光/姿势变化，材料够时史蒂夫无任何暗示——**M7**
4. 换装免费无确认、无「战力」数值、**不统计不展示换装次数**——评审问 5
5. 配件目录无稀有度标签、无概率、全固定价——继承禁抽卡
6. 家长设置加「史蒂夫养成」开关（默认开）：关 = 隐藏入口与计数，
   史蒂夫**保持当前装扮**；同屏放养成版观察清单（评审已写好，静态文案）
7. 重置进度二次确认文案追加「史蒂夫的装备和你点亮的星星也会一起消失」

## 7. 精灵渲染（按件混搭的实现）

头/躯干/腿在 24×40 画布坐标恒定（`8,8 / 8,16 / 8,28`，五姿势同），手臂随姿势
变——但装备不覆盖手臂，故**一套装备叠加层适配全部姿势**。

- `gen-steve.mjs` 扩展：输出 16 件装备叠加 PNG（`eq-*.png`，仅覆盖对应身体
  区块的换色网格）+ 12 件配件 PNG + **裁剪偏移 manifest**（生成
  `src/ui/components/steveMeta.ts`：每姿势 `{x0, y0}`——精灵按内容 bbox 裁剪，
  叠加层定位需减去该偏移）。manifest 是生成的纯数据，单测校验完整性。
- `Steve` 组件加 `equipped` prop：容器内基础精灵 + 按 manifest 绝对定位的
  叠加 `<img>`，全部 `image-rendering: pixelated`，缩放系数同源。
- 装备叠加层配色：皮革 `#8a5a2b` 系 / 铁 `#c6c6c6` 系 / 金 `#fcdb05` 系 /
  钻 `#4aedd9` 系，各带明暗两档（同现有斜角明暗逻辑）。

## 8. 语音与文案（新增 TTS 行）

进养成屏欢迎、制作成功（「铁靴做好了！」）、点星、星座集齐、材料说明卡
（点矿石念来源：「煤：每走完一关，挖到一块」）。**全部新中文进源码后必须
`bash scripts/subset-font.sh` 重跑子集**——charset 守卫测试会拦，属预期流程。

## 9. 测试策略

奖励核心是纯函数，**这次是真 TDD**（对比 UI 重构的三层验证）：

- 公式单测：五矿收入对照手算样例；`P` 只计首答即对
- 性质测试：收入对 Progress 增长单调（farm-proof）；`balance ≥ 0` 恒成立；
  `craft` 幂等；顺序解锁不可越阶；兑换链算术
- **画像仿真测试**：常规/跳级/弱三条脚本化周进度流，断言评审 §F 时间线
  （皮革靴首会话可达、弱孩子无死锁、跳级不需回刷——直接把评审结论变成回归测试）
- 目录完整性：28 个 id 唯一、材料与价格匹配、每件装备有叠加素材、manifest 全姿势覆盖
- UI 层照旧：构建 + 逐屏目视

## 10. 验收（沿评审 §验收标准）

首开自助完成第一件制作；上线两周首答正确率不降、每题用时不缩 >15%；
展示物行为而非兑换机行为；练习模式频次上升；无回刷；皮革靴首会话落袋、
常规钻套 8–10 周、任意「新东西」空窗 ≤2 周；周答题量是换装的唯一裁判。
调参判据照评审 §G，上线后按表改数不凭感觉。
